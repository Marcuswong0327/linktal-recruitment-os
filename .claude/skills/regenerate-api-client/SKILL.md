---
name: regenerate-api-client
description: Regenerate apps/api/openapi.json and the apps/web orval-generated API client after changing a NestJS controller, DTO, or entity in apps/api/src. Use whenever a backend route, request DTO, or response shape changed and the frontend's generated hooks/types need to catch up. Triggers on "regenerate api client", "regenerate openapi", "orval", "update generated types", or right after editing files under apps/api/src/**/*.controller.ts, **/dto/*.ts, **/entities/*.ts.
allowed-tools: Bash(pnpm *), Bash(git *)
---

Run this after any change to an API controller, DTO, or entity — new/renamed
endpoints, changed request/response shapes, new enum values, etc. The spec
generation is fully offline (`preview: true` in
`apps/api/scripts/generate-openapi.ts` builds the module graph without
starting the server or touching the database), so this is safe to run anytime,
including with no `DATABASE_URL` configured.

1. **Regenerate the OpenAPI spec:**
   ```
   pnpm --filter api openapi:gen
   ```
   Writes `apps/api/openapi.json`.

2. **Regenerate the web client from that spec:**
   ```
   pnpm --filter web generate-api
   ```
   Runs `orval`, rewriting `apps/web/src/lib/api/generated/**`.

3. **Typecheck the backend:**
   ```
   pnpm --filter api typecheck
   ```

4. **Typecheck the frontend:**
   ```
   pnpm --filter web typecheck
   ```
   New/renamed fields routinely break frontend callers (missing property,
   renamed DTO field, a status enum that gained/lost a member) — that's the
   whole point of running this step, not a side effect to ignore.

5. **Triage frontend typecheck failures before touching anything:**
   - `git stash && pnpm --filter web typecheck 2>&1 | tail -30 && git stash pop`
     to see which failures already existed before this change.
   - Any failure that disappears once your diff is restored is caused by
     *this* change — fix the frontend call sites (or the backend shape, if
     the frontend was right and the backend regressed).
   - Any failure present in both runs is pre-existing drift, unrelated to
     this change. Don't fix it as a drive-by — mention it to the user instead.

6. **Sanity-check the diff scope:**
   ```
   git status --short
   git diff apps/web/src/lib/api/generated/types/index.ts
   ```
   The generated diff should map 1:1 onto the backend change (new DTO
   exports, changed operation signatures). A much larger diff than expected
   usually means the backend change was bigger than intended, or the spec was
   stale before you started.

Do not hand-edit anything under `apps/web/src/lib/api/generated/` — it's
fully regenerated by step 2 and any manual edit is silently lost next run.
